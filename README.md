 1. 프로젝트 개요
이 프로젝트에서는 터미널에서 메뉴 번호를 입력하여 프롬프트를 관리하는 Python 프로그램을 제작하였습니다. 프롬프트 추가, 전체 목록 보기, 카테고리별 보기, 검색, 상세 보기, 즐겨찾기 추가·해제와 즐겨찾기 목록 보기 기능을 사용할 수 있습니다.
필수 기능은 따로 설치해야 하는 프로그램 없이 Python 기본 문법만 사용하여 구현하였습니다. 프롬프트는 리스트와 딕셔너리에 저장하였으며, 각 프롬프트에는 제목, 내용, 카테고리, 즐겨찾기 여부가 들어 있습니다. 보너스 기능으로 JSON 저장·불러오기와 카테고리별 Markdown 내보내기를 추가하였습니다. 따라서 프로그램을 종료한 후 다시 실행해도 추가한 내용과 즐겨찾기 상태가 유지됩니다.
필수 기능에서는 프로그램 실행 중에 데이터를 유지하도록 요구합니다. 이 프로젝트는 보너스 1을 추가로 구현하여 프로그램을 종료한 후에도 프롬프트와 즐겨찾기 상태가 JSON 파일에 유지되도록 확장하였습니다.

최종 결과  프롬프트 관리 프로그램의 필수 기능을 모두 구현하였습니다. GitHub 저장소 업로드, 16개 이상의 기능·문서 단위 커밋과 기능 브랜치 병합을 완료하였습니다. 보너스 기능으로 JSON 저장·불러오기와 Markdown 내보내기를 구현하였으며, 중복 제목 방지 기능도 추가하였습니다.

카테고리를 추가하거나 삭제할 때는 prompt_manager.py의 CATEGORIES 목록을 수정하고, 기존 prompts.json에 저장된 category 값도 함께 확인합니다.
카테고리 이름을 바꿔도 기존 JSON 데이터는 자동으로 변환되지 않습니다. 따라서 기존 프롬프트의 category 값은 prompts.json에서 새 이름으로 직접 확인·수정해야 합니다. 예시 항목은 title, content, category, favorite 네 개의 키로 구성됩니다.

 5. 필수 기능 구현 및 실행 결과
 5.1 메뉴 선택과 프로그램 실행
프로그램을 실행하면 1번부터 8번까지의 기능 메뉴와 0번 종료 메뉴가 표시됩니다. 사용자가 번호를 입력하면 해당 기능이 실행되며, 작업이 끝나면 다시 메인 메뉴로 돌아옵니다. 잘못된 번호를 입력하면 안내 문장이 표시되고 메뉴가 다시 나타납니다.
메뉴에 없는 번호는 안내 후 메뉴를 다시 표시하고 새 번호를 입력받습니다. 프롬프트 번호는 1부터 전체 프롬프트 개수까지만 사용할 수 있습니다. 글자를 입력하면 숫자 입력 안내가 표시되며, 목록에 없는 번호는 잘못된 번호로 처리합니다. JSON 파일이 없을 때는 기본 프롬프트가 들어 있는 새 파일을 만들어 프로그램이 계속 실행되도록 하였습니다.

입력 범위  메인 메뉴는 0~8만 허용합니다. 9를 입력하면 '잘못된 번호입니다. 다시 입력해주세요.'라고 안내한 뒤 메뉴를 다시 보여줍니다.

주석  프로그램을 실행하면 1번부터 8번까지의 기능과 0번 종료 메뉴가 표시됩니다. 사용자는 원하는 번호를 입력하여 기능을 선택할 수 있습니다.



그림 4. 잘못된 메뉴 번호 입력 안내와 메뉴 재표시 결과

 5.2 프롬프트 추가 및 목록 보기
제목, 내용, 카테고리를 입력하면 새 프롬프트가 등록됩니다. 아무것도 입력하지 않으면 다시 입력하라는 안내가 표시됩니다. 새 프롬프트는 처음에는 즐겨찾기하지 않은 상태(False)로 저장됩니다. 목록 화면에는 번호, 카테고리, 제목과 즐겨찾기 별표가 함께 표시됩니다.
제목, 내용과 카테고리에는 별도의 최대 길이와 허용 문자 제한을 두지 않았습니다. 다만 빈칸은 저장할 수 없으며, 같은 제목이 이미 있으면 다른 제목을 다시 입력해야 합니다.
입력 예시는 제목 '블로그 제목 생성', 내용 '주어진 키워드로 제목을 5개 작성해주세요', 카테고리 '텍스트 생성'입니다.


그림 5. 새 프롬프트가 전체 목록에 반영된 결과
주석  ‘블로그 제목 생성’ 프롬프트를 추가한 뒤 전체 목록을 확인한 화면입니다. 새 프롬프트가 5번으로 등록되었으며, 전체 개수도 5개로 늘어났습니다.

중복 제목 방지 기능은 prompt_manager.py의 is_duplicate_title()과 add_prompt()에서 처리합니다. 입력한 제목을 기존 프롬프트 제목과 비교하며, lower()를 사용하여 영어 대문자와 소문자를 같은 글자로 판단합니다. 같은 제목이 있으면 저장하지 않고 다른 제목을 다시 입력하도록 안내합니다.


그림 6. 이미 등록된 제목의 중복 저장을 막는 실행 결과
주석  이미 등록된 ‘Python 기초 설명’을 다시 입력한 화면입니다. 같은 제목이 있다는 안내가 표시되고 다른 제목을 다시 입력하도록 처리되어 중복 제목이 저장되지 않습니다.

 5.3 카테고리별 조회
카테고리 목록에서 번호를 선택하면 해당 카테고리의 프롬프트만 모아서 보여줍니다. 텍스트 생성 카테고리를 선택한 결과, 해당 프롬프트 3개가 표시되었습니다.
선택한 카테고리 이름과 프롬프트의 category 값이 정확히 같을 때만 결과에 포함됩니다. ‘기타’를 선택하면 사용자가 직접 입력한 카테고리 이름을 그대로 저장하고 조회합니다.
선택한 카테고리에 속한 프롬프트가 하나도 없으면 '해당 카테고리의 프롬프트가 없습니다.'라고 안내하고 메인 메뉴로 돌아갑니다.


그림 7. 텍스트 생성 카테고리별 조회 결과
주석  텍스트 생성 카테고리를 선택한 화면입니다. 해당 카테고리에 들어 있는 프롬프트 3개만 표시되어 카테고리별 조회 기능이 정상적으로 작동하는 것을 확인하였습니다.

 5.4 프롬프트 검색
영어 검색어는 대문자와 소문자를 따로 구분하지 않도록 모두 소문자로 바꾼 뒤 찾습니다. 입력한 말이 프롬프트의 제목이나 내용에 들어 있으면 검색 결과에 표시됩니다. ‘블로그’를 검색한 결과, 프롬프트 2개가 검색되었습니다.
검색 로직은 prompt_manager.py의 search_prompt()에 있습니다. 검색어가 제목이나 내용의 일부에 들어 있어도 찾을 수 있는 부분 일치 방식입니다. lower()로 영어 대소문자를 같게 비교하지만, 불용어 제거와 정규식 검색은 사용하지 않았습니다. 한글과 영어는 검색할 수 있지만 띄어쓰기, 특수문자, 오타를 자동으로 고쳐주지는 않습니다.


그림 8. 제목 또는 내용 기준 키워드 검색 결과
주석  검색어로 ‘블로그’를 입력한 화면입니다. 제목이나 내용에 ‘블로그’가 들어 있는 프롬프트 2개가 검색되었습니다.

 5.5 프롬프트 상세 보기
프롬프트 번호를 입력하면 제목, 카테고리, 즐겨찾기 여부와 내용 전체가 구분선과 함께 표시됩니다. 글자를 입력하거나 목록에 없는 번호를 입력하면 잘못된 입력이라는 안내가 표시된 뒤 메뉴로 돌아갑니다.


그림 9. 블로그 제목 생성 프롬프트의 상세 보기
주석  5번 프롬프트의 상세 내용을 확인한 화면입니다. 제목, 카테고리, 즐겨찾기 여부와 전체 내용이 함께 표시되었습니다.

 5.6 즐겨찾기 관리
즐겨찾기를 선택하면 favorite 값이 False에서 True로 바뀝니다. False는 즐겨찾기하지 않은 상태이고, True는 즐겨찾기한 상태를 뜻합니다. 즐겨찾기 목록에서는 True인 프롬프트만 별표와 함께 표시됩니다.
즐겨찾기 상태가 바뀌면 추가 또는 해제되었다는 확인 메시지가 표시됩니다. 같은 프롬프트 번호를 다시 선택하면 이전 상태로 되돌릴 수 있습니다.


그림 10. 즐겨찾기 프롬프트만 모아서 출력한 결과
주석  즐겨찾기로 선택한 프롬프트 2개가 별표와 함께 표시된 화면입니다. 즐겨찾기에 추가한 프롬프트만 모아서 확인할 수 있습니다.

 7. Git 작업 기록 및 브랜치 병합
프로젝트 폴더에서 Git 기록을 시작한 뒤, 기능을 하나씩 만들 때마다 커밋으로 저장하였습니다. 프롬프트 목록 기능은 feature/prompt-list 브랜치에서 작업하였습니다. 보너스 기능은 feature/json-storage 브랜치에서 작업한 뒤 main 브랜치에 병합하였습니다. 병합된 기록은 Git 로그의 선 모양으로 확인할 수 있습니다.
커밋은 작업 내용을 한 번 저장한 기록입니다. 브랜치는 main과 분리된 별도의 작업 공간이며, 병합은 브랜치에서 만든 기능을 main에 합치는 과정입니다.
프롬프트 목록 브랜치는 git checkout -b feature/prompt-list, JSON 저장 브랜치는 git checkout -b feature/json-storage 명령으로 만들었습니다. 기능을 확인한 뒤 git checkout main으로 main에 돌아와 git merge 브랜치이름 순서로 합쳤습니다.
