 1. 프로젝트 개요
 1.1 기획 배경
클래식 음악을 듣고 싶어도 곡명이나 작곡가를 잘 모르면 무엇을 선택해야 할지 막막할 수 있다. 특히 하루의 감정에 맞는 음악을 찾으려면 검색어를 직접 정하고 여러 곡을 비교해야 한다. ‘클래식 하루’는 이 불편을 줄이기 위해 사용자의 현재 기분을 첫 입력값으로 삼고, AI가 감정과 상황에 맞는 클래식 음악을 추천하는 서비스로 기획했다
 1.2 문제 정의와 해결 방향

 2. AI 디자인 생성 과정

기록 기준
아래 프롬프트는 최종 화면을 만드는 동안 사용한 요구사항과 수정 방향을 보고서용으로 정리한 것이다. 단계마다 스타일, 레이아웃, 색상, 화면 역할, 텍스트 정확성을 구체화했다

 2.1 초안 프롬프트
“클래식 음악 추천 모바일 앱 UI를 디자인해줘. 사용자가 오늘의 기분을 선택하면 AI가 클래식 곡을 추천하는 서비스야. 네이비와 골드 색상을 사용하고 고급스럽고 따뜻한 분위기로 만들어줘. 메인 화면, 추천 목록 화면, 곡 상세 화면을 세로형 모바일 UI로 구성해줘.”

Maintain one consistent design system: deep navy #071D35, warm gold #C78A19, ivory background, soft shadows, rounded cards, refined classical mood, generous spacing, and high Korean legibility. Do not distort or misspell Korean text.
Screen 1 — Main: dark navy curved header with logo, menu and notification icons; title ‘클래식 하루’ and subtitle ‘CLASSIC DAY’. Main question ‘오늘, 어떤 기분이신가요?’ with supporting copy. Four large emotion cards: ‘편안함 / 마음이 차분해지고 싶을 때’, ‘활력이 필요해요 / 에너지를 충전하고 싶을 때’, ‘잠들기 전이에요 / 지친 하루를 마무리할 때’, ‘집중하고 싶어요 / 몰입이 필요할 때’. Add CTA area and persistent bottom navigation.
Screen 2 — AI recommendation list: header ‘AI 추천 클래식’, selected mood ‘편안함을 위한 추천’, short explanation, and three ranked recommendation cards with composer portrait, composer, title, two mood tags, one-sentence description, and play button. Use Chopin Nocturne Op.9 No.2, Debussy Clair de Lune, and Bach Air on the G String.
Screen 3 — Detail: Chopin portrait, category chip ‘클래식’, title ‘녹턴 2번 Op.9 No.2’, composer ‘쇼팽 (F. Chopin)’, mood tags, short description, ‘AI 추천 이유’, ‘감상 포인트’, two similar tracks, favorite icon, and a bottom music player. Keep the same bottom navigation.  3.2 화면별 후가공 내역

화면
핵심 후가공
메인
‘잠들기 전이에요’가 축소 화면에서 ‘전이애요’처럼 보이는지 확대 확인했으며, 실제 자소와 맞춤법이 정상임을 확인함. 전체 이미지는 412×917 Figma 프레임에 맞춰 크기와 위치를 조정
추천 목록
곡명·작곡가·태그와 초상 이미지의 이상 여부를 확인하고, 전체 이미지를 목록 프레임에 맞춰 배치
상세
녹턴 곡명, 쇼팽 표기, AI 추천 이유와 감상 포인트의 가독성을 확인하고, 전체 이미지를 상세 프레임에 맞춰 배치


한글 확대 검수 결과
메인 화면의 ‘잠들기 전이에요’는 작은 화면에서 ‘에’가 뭉쳐 보여 오타처럼 느껴졌지만, 원본 이미지를 확대해 확인한 결과 ‘잠들기 전이에요’로 정확하게 표시되어 있었다. 따라서 별도의 Figma 텍스트 수정은 진행하지 않았다

 3.3 후가공 전후 차이
· 	전: 화면마다 텍스트 크기와 여백이 달라 시선 흐름이 불안정함 → 후: 제목, 본문, 보조 문구, 태그의 위계가 통일됨
· 	전: AI 생성 이미지의 한글이 깨질 가능성이 있음 → 후: 최종 이미지의 문구를 확대 검수하고 가독성 문제가 없는 결과를 사용함
· 	전: 화면은 독립된 시안에 가까움 → 후: 클릭 가능한 요소와 이동 목적지를 연결해 프로토타입으로 완성함
· 	전: AI 생성 이미지의 세부 표기가 부정확할 수 있음 → 후: 한글 맞춤법, 곡명, 작곡가명, 버튼 문구를 사람이 검수함
 3.4 저작권·윤리 및 레퍼런스 기록
본 프로젝트의 UI 화면은 ChatGPT 이미지 생성으로 만든 시안을 바탕으로 Figma에서 후가공했다. Pinterest, Dribbble 등에서 타인의 UI 작업물을 캡처하거나 그대로 복제해 제출하지 않았으며, 외부 UI 디자인 레퍼런스를 제출 이미지에 직접 사용하지 않았다

 8. 학습 결과 및 자기평가
 8.1 프롬프트 구성 요소가 결과에 미친 영향
초안에서는 ‘클래식 추천 앱’이라는 주제와 분위기만 전달했기 때문에 화면별 정보 구조가 일정하지 않았다. 수정 단계에서 프레임 크기, 화면 역할, 감정 카드 문구, 이동 경로를 명시하자 세 화면의 목적이 분명해졌다. 최종 단계에서는 색상 코드, 곡 정보, 태그, 버튼, 텍스트 정확성까지 지정해 시각적 일관성과 콘텐츠 완성도를 높일 수 있었다. 이를 통해 스타일뿐 아니라 레이아웃, 문구, 인터랙션 조건을 함께 작성해야 원하는 UI 결과에 가까워진다는 점을 확인했다
 8.2 AI 생성 이미지의 문제점과 수정
AI는 짧은 시간에 전체 분위기와 화면 구성을 제안하는 데 유용했지만, 한글 텍스트와 세부 정렬, 아이콘 일관성, 실제 클릭 동작까지 자동으로 검증하지는 못했다. 이번 작업에서는 최종 생성 이미지의 한글과 곡 정보를 확대해 확인하고, 가독성 문제가 없는 결과를 선택했다. 이후 이미지를 412×917 Figma 프레임에 맞춰 배치하고 Hotspot을 추가했다. 텍스트를 별도의 Figma 텍스트 레이어로 다시 입력하지 않았으므로, 보고서에도 실제 작업 범위만 기록했다
 8.3 프로토타입 설계에서 배운 점
UI 이미지 세 장을 나열하는 것과 실제 사용 흐름을 만드는 것은 다르다. 이번 작업에서는 메인에서 감정을 선택하고, 목록에서 곡을 선택한 뒤, 상세 화면에서 추천 근거를 확인하는 핵심 시나리오를 먼저 정의했다. 그 후 해당 행동이 일어나는 카드와 버튼에 Hotspot을 연결했다. 이 과정을 통해 화면 수를 늘리는 것보다 사용자의 목적이 다음 화면으로 자연스럽게 이어지도록 설계하는 것이 중요하다는 점을 배웠다

 D.4 후가공 표준 절차
· 	1단계 — 원본 확인: 생성 이미지를 200% 이상 확대해 한글 자소, 띄어쓰기, 곡명, 작곡가명, 얼굴·손·아이콘 왜곡을 확인한다.
· 	2단계 — 수정 방식 결정: 작은 부분 오류라도 인페인팅을 사용하지 않고, 전체 화면 재생성 또는 오류가 없는 결과 선택 중 하나를 사용한다.
· 	3단계 — 해상도 판단: 원본이 목표 프레임보다 큰지 확인한다. 이번 작업은 원본이 더 커서 AI 업스케일을 적용하지 않는다.
· 	4단계 — Figma 배치: Android Compact 412×917 프레임에 이미지를 넣고 비율·위치·잘림을 조정한다.
· 	5단계 — 텍스트 재검수: ‘잠들기 전이에요’, 작곡가명, 곡명, 태그와 버튼 문구를 다시 확대 확인한다.
· 	6단계 — Prototype 검수: 메인→목록→상세 이동, 뒤로가기, 홈 이동을 Present 모드에서 각각 실행한다.
